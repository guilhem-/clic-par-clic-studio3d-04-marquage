# Marking AI-generated renders — IPTC and XMP metadata, optional visible banner

Code for module 4 of the “Click by Click” series **Building an agent-ready AI service: the 3D studio**
(also published in French as « Clic par clic » and in German as « Klick für Klick »).

Video: {{video}}

## Goal

An image from the studio looks like a product photo. This repository teaches the module 3 studio
to **mark every render as generated by artificial intelligence**, on two levels:

- **invisible, always**: in the PNG file, an XMP packet with the IPTC source type
  `trainedAlgorithmicMedia` (“created using generative AI”), the creation date, the generator
  “AI studio3D” and the unique id of the request, plus PNG text fields (`Software`,
  `Creation Time`, `Source`, `Disclaimer`); in the 3D model (GLB), the `asset.generator` field
  and the same information in `asset.extras`;
- **visible, optionally**: a banner that is **always identical**, at the bottom right of the image
  (`AI studio3D · YYYY-MM-DD`, UTC date of the end of the render), requested by the user (the model
  passes `visible_marking: true` to the MCP tool) or enforced by the organization.

The marking is applied by the **worker, after Blender**, before the files are stored: the scene
code, written by the model, can neither avoid nor change it. A marking error puts the request in
error: no unmarked file ever goes out.

## Contents

| File | Role |
|---|---|
| `studio/marking.py` | **New.** XMP packet, PNG text fields (Pillow), visible banner (DejaVu Sans font, 22 px, black at 60 %, 16 px margin), rewrite of the GLB JSON chunk |
| `studio/api.py` | Module 3 MCP server, plus: optional `visible_marking` parameter of `submit_render` (and its description for the model), the organization's policy, a unique id (UUID) for each request; `render_status` and `my_renders` return the actual choice |
| `studio/worker.py` | Module 3 worker, plus: the marking is called right after Blender, before writing to Redis |
| `studio/common.py` | Policy read from the environment (`MARKING_VISIBLE_DEFAULT`, `MARKING_VISIBLE_ENFORCED`), new fields of the request |
| `studio/render.py`, `studio/metrics.py` | Unchanged since module 3 |
| `studio/Dockerfile` | Image `studio3d:3`: the module 3 image, plus Pillow 12.3.0 and the DejaVu Sans font (`fonts-dejavu-core`) |
| `k8s-scale.yaml` | Module 3 manifest, plus the two policy variables on `studio-api` (`"no"` by default) |
| `read_marking.py` | Reads the marking of a PNG or a GLB, standard library only (ExifTool does not read glTF) |
| `test/marked-render.sh` | Two renders (without, then with the banner), download through the signed links, marking shown |
| `open-webui/` | Identity header of the MCP connection and system prompt of the “Studio 3D” model, with one more sentence about the visible notice |
| `.env.example` | Variables to fill in (token, Redis password), without any value |

## Prerequisites

- The scaled studio of **module 3** (repository
  [`clic-par-clic-studio3d-03-grafana`](https://github.com/guilhem-/clic-par-clic-studio3d-03-grafana)):
  Redis, KEDA 2.21, `studio` secret, “Studio 3D” connection and model in Open WebUI.
  The module 3 observability is not needed.
- Docker, `kubectl` and a Kubernetes cluster (the video uses **k3d**, cluster `tterm`, Traefik
  published on port 8080 of the machine).
- On your workstation: [ExifTool](https://exiftool.org/) 13.x (Windows: `winget install OliverBetz.ExifTool`)
  and Python 3.10 or later for `read_marking.py`.

## Step-by-step installation

1. **Image** of the studio, with the marking:

   ```bash
   docker build -t studio3d:3 studio
   k3d image import studio3d:3 -c tterm      # k3d; otherwise, push the image to your registry
   ```

2. **The organization's policy.** In `k8s-scale.yaml`, on `studio-api`:

   | Variable | `"no"` (default) | `"yes"` |
   |---|---|---|
   | `MARKING_VISIBLE_DEFAULT` | no banner if the user asks for nothing | banner when the user does not say |
   | `MARKING_VISIBLE_ENFORCED` | the user chooses | banner always, whatever the user asks |

   The invisible marking cannot be turned off.

3. **Studio**:

   ```bash
   kubectl apply -f k8s-scale.yaml
   kubectl -n studio3d rollout restart deployment/studio-api
   kubectl -n studio3d rollout status deployment/studio-api
   ```

4. **Open WebUI**: in the “Studio 3D” model, replace the system prompt with the one in
   `open-webui/system-prompt.txt` (one sentence added: `visible_marking` set to `true` only if the
   user asks for a visible notice). Refresh the MCP connection so that the new parameter of the
   tool is read.

5. **Try it.** In Open WebUI: “Create a yellow desk lamp, standing on a wooden desk.”, then
   “Make the same lamp again, with the visible notice.”, then “How are my renders doing?”.
   Or, without Open WebUI, with a local access and the token:

   ```bash
   kubectl -n studio3d port-forward svc/studio 8000:8000 &
   export STUDIO_TOKEN=…          # the one in the "studio" secret
   ./test/marked-render.sh        # on Windows (Git Bash): PYTHON=python ./test/marked-render.sh
   ```

6. **Read the marking** of a downloaded file:

   ```bash
   exiftool -G1 -s -XMP:all -PNG:all render.png
   python read_marking.py render.png
   python read_marking.py model.glb
   ```

## Good to know

- **Where to mark?** Never in the scene code: it is written by the model, which could forget it
  or change it. The worker marks after Blender exits, in its own process.
- **Source type.** IPTC distinguishes `trainedAlgorithmicMedia` (created using generative AI) from
  `algorithmicMedia` (pure algorithm, without training data). Here, the scene is composed by a
  language model and then computed by Blender: we choose `trainedAlgorithmicMedia`, the cautious
  choice, since the content is decided by a trained model.
- **An always identical banner**: same font, same size, same place; only the date changes.
  A banner that varies is a banner nobody recognizes.
- **The number and the id**: the request number is for humans, the UUID
  (`xmpMM:DocumentID`, `urn:uuid:…`) for traceability.
- **Limits**: a screenshot, or a social network that recompresses the image, erases the metadata;
  a banner can be cropped. Possible next layers: an invisible watermark in the pixels (for example
  TrustMark, open source), and a C2PA signature, which requires a private key and a trusted
  certificate (with a self-signed certificate, verification tools show it as unknown): a project of
  its own, not covered here. The IPTC vocabulary used here is the one of C2PA actions: moving to
  C2PA later does not change the information, only its guarantee.

## What the texts say (not legal advice)

Pointers checked in October 2026, **to be checked with your legal team**:

- European Union: Regulation (EU) 2024/1689 (Artificial Intelligence Act), Article 50,
  “Transparency obligations for providers and deployers of certain AI systems”: providers of
  systems that generate images ensure that their outputs are marked in a machine-readable format
  and detectable as artificially generated (paragraph 2); deployers disclose deep fakes
  (paragraph 4). Obligations applicable since 2 August 2026; under the “Digital Omnibus” regulation
  on AI, systems already placed on the market before that date had until 2 December 2026 for the
  marking. The European Commission's voluntary Code of Practice on marking and labelling
  AI-generated content (June 2026) recommends several layers of marking.
- China: measures for labeling AI-generated synthetic content (in force since September 2025) and
  standard GB 45438-2025: visible label and marking in the file.
- California: AI Transparency Act (SB 942, amended by AB 853): marking in the file, visible notice
  at the user's choice.

An organization that puts its own studio into service may be considered a provider.
